# 文字类型与表格识别质量

从「Excel 表格」「提取表格」或 PDF 转 Excel 进入时，先明确选择「印刷表格」或「手写或混合」。手写填写的印刷表单也应选择后者；已有「手写转 Excel」快捷入口仍直接进入手写流程。校对页标题区分两种模式，旋转、重开与草稿保存保留所选模式。

这里采用用户确认文字类型，没有把置信度包装成自动字体分类器。高分手写、低分印刷都可能出现；目前不宣称可以自动准确区分所有字体。

## 生成前检查

每个选中页在构表前先检查文字识别证据，包括按字符数加权的低分比例、空读框比例、缺少分数的比例，以及两路高分输出的编辑差异。评分不使用中文比例、户号格式、金额或常见词白名单，也不改写原始识别文字。

印刷流程先检查 ML Kit 的分数；不足时使用原有 PaddleOCR mobile 识别器复核对应文字区域，结合其分数与两路文字一致程度再判断，避免单一阈值误拒绝清晰内容。复核是支持证据，不是准确率。手写或混合流程沿用已有 server/mobile 两个识别器，检查空读、分数和明显分歧。模型输出出现非有限数值会中止识别。[ML Kit 行级置信度接口](https://developers.google.com/android/reference/com/google/mlkit/vision/text/Text.Line)

明显不可靠或没有可提取表格的页，会提示页码并提供返回原图、重试和重新选择文字类型。全部选中页通过后才保存新校对稿或生成文件；一页失败不会偷偷略过该页，也不会替换已经人工修改的旧稿。

所有权重、字典及原生库沿用 rc.13，没有新增字体分类模型、量化或联网识别。规则仅拦截明显失败，两个识别器仍可能对同一个错误一致。通过检查后仍须核对编号、人名、金额与行列对应；目前不能保证整张表无错字。印刷流程的检查主要针对构表前的文字行，不等于对后续每个单元格的识别正确性作保证。

## 旧稿和导出

新版在校对稿中保存质量规则版本与识别模式。旧版稿件没有记录时，会先提示，可保留人工修改继续校对，或重新识别。导出旧稿须明确确认已核对；普通表格导出也增加核对确认。手写校对、候选、逐项确认、原图分列、缩放及行列尺寸编辑继续保留，调整分列不会丢失质量记录。

## 验证边界

仪器测试覆盖普通入口选手写、两模式草稿隔离、旧稿确认、拒绝后保留人工更正、多页中途失败、模式重建恢复，以及清晰印刷中英数字表。针对性私有样张探针由设备专用目录读取，缺样张会明确跳过；照片和识别内容不随源码或 APK 分发。正式交付的运行结果记在[验证记录](validation.md)。

测试不代替多品牌真机验收，也没有复现用户尚未提供原始照片的具体失败。质量门槛属于保守的工程规则，尚无跨书写者、跨机型的误拒率和漏拦率统计。
